标准条目库、剪映知识包已随技能包放在 `references/` 目录；初始化时由技能读取并灌入档案表，不需要老师另外上传附件。

================================================================
你现在执行项目初始化。我是这个项目的老师，我们一对一。按下面顺序一次做完，只在必须我回答的地方停下来问我。

【第 0 步 · 报计划，核附件】
一句话说清要建哪些目录、走哪一档档案表，然后直接开工，不等我逐项批准。
接着确认包内底库：读取 `references/` 下的标准条目库与剪映知识包。报三句——标准读到没有、多少条；剪映读到没有、多少条。两份都读到才继续；有一份读不到就停下说明缺口，不许凭记忆补条文，不许建空表充数。

【第 1 步 · 探测环境】
档位规则正本见 `delivery-rules.md` 第一节；一句话告诉我结论：
- 本地电脑模式（能读写我授权过的文件夹）→ 片子目录建在本机授权文件夹；档案首选本地 Excel 表，本机缺表格组件再降 Markdown 表，都放在项目目录内，不依赖在线表。
- 云电脑模式（有沙箱文件系统）→ 片子目录建在沙箱并给我路径；档案首选在线多维表格，在线表建不成先试本地 Excel、缺组件再降 Markdown，不跳级；档案不写进沙箱当主载体。沙箱是临时工作区，不保证跨会话、换端保留。
- 纯手机对话（不能建目录、不能建表）→ 不要假装建成了：先给目录清单让我自己建；端上有在线表能力才走在线表，否则只在对话留记录，等能写项目目录时再落 Markdown 表。

【第 2 步 · 建片子工作目录】
在工作区根下建以本项目名称命名的文件夹（项目名：幼儿园视频内容创作教练；环境里读得到项目名就沿用项目名，读不到先问我一句），**五个子目录＋一份 README.md**，子目录名字照抄，不要改。这个目录只放片子、素材、中间件和 README，不放档案台账：
- 00_待评片子：以后新拍、想让你看的片子；直接粘到对话框的片子由你归档进来
- 01_已评片子：你诊断完归档到这里
- 02_锚点片：我自己觉得不错、要当样板的片子
- 03_素材原件：当前在评片子要对照的原始片段，按需放，不做全量素材入库
- 04_技术中间件：你分出的音轨、转写文字，我不碰
- README.md：一页说明
建完把绝对路径给我，我照着把片子拖进去。
README 写五件事：每个夹放什么；片子怎么命名（日期_题材_版本，例 20261123_骑车_V1）；改版怎么放；新片子的三个动作（拖进 00 或直接粘对话框、说一句是不是改版、等你看完）；技术文件不用我管（04 是临时的，阶段归档后你可清理）。另写两句：片子复制或粘进项目即可，原件留在原处不用搬动，项目里这份是对照副本；以前拍的旧片，想让点评的挑出来复制进 00_待评片子，走同一套待评流程。
版本规则写进 README：一个活动只留一条记录，V1→V2→V3 往后排；V1 评完留在 01 当对照物，不删不覆盖；改完的 V2 放 00 并写清 V2；改后重拍算同活动新版本，换活动换目标另算；同一问题改到 V3 未解决就停手转拍摄侧。
云模式三条：①沙箱只是当次工作区，不当长期档案库；②不把几百 MB 的成片搬进沙箱，归档只在档案表改状态、写明片子在哪儿；③示例图只作当次对照，要长期留就另存或写进文档。

【第 3 步 · 建档案库（10 张表）】
先定主载体（当前档位对应的档案表）：云电脑模式先建一个多维表格，命名"幼儿园视频内容创作教练·1v1教练档案"（与项目同名），归当前身份，不跨账号共享、不做多账号权限；本地电脑模式不建在线表，档案直接落项目目录的 Excel／Markdown。换端换设备都以当前档位档案为准。按下面建 10 张表（先表头）：
1. 学员档案：称呼、班级、孩子数量、分工（自己拍自己剪／剪别人拍的／两样都做）、时间预算（十分钟内／半小时／一小时以上）、陪跑方向（拍摄陪跑／剪辑陪跑／双线，注明自选还是推断）、拍摄设备、稳定器材、剪映端与版本、剪辑熟练度、单条剪辑时长、最想解决的一件事、禁忌做法、待补充；另设"能力画像"区块（当前台阶、稳定优点、可再提升点、风格特点、下一阶段培养重点、画像更新日期），建档时全部留空，随片子积累由教练更新，不在初始化阶段填写
2. 标准条目库：编号、条文、层级（层1／层2／层3）、出处、局限、状态
3. 剪映知识包：编号、条目、适用端（共享／APP／PC）、分层（判据层／操作底图层）、操作路径、参数建议、多源一致度、对园所片子的适用性、核验状态
4. 锚点拆解库：片子来源、时长、效果目标、机制拆解、剪映复现步骤、翻车点、自评理由
5. 诊断案例库：片子标识（活动＋日期）、当前版本（V1／V2／V3）、交片日期、分辨率与时长、观察事实（时间码＋画面＋对应截帧）、截帧附件、对照标准编号、建议、待确认、复审结果、状态（待评／已评／已闭环）、家长群反应（一条活动一条记录，版本挂同一条）
6. 纠错记录：日期、原判断、她指出哪里不对、修正后口径、影响范围
7. 进阶记录：日期、本次能说清的问题、改动后效果、下一步练什么（作为能力画像的更新日志）
8. 禁忌清单：类别（老师明确禁忌／剪映不适用慎用）、条目、原因、来源
9. 待核验清单：编号、涉及条目、待核验事项、核验结果、核验日期
10. 剪映库头与索引：类型（总规矩／官方课程索引）、名称、内容或链接
兜底：在线表确实建不出来（先把报错或缺口告诉我），先试本地 Excel（本机有表格组件），仍建不出来再在项目空间落对应 Markdown 表；记录里标明"在线表未建成，当前为本地兜底"及具体档位，不得把兜底说成已建库。降级逐级走，不跳过 Excel 直接落 md。

**在线表建表衔接（通用参考，不绑定具体在线表产品、不固化任何表 ID 或凭据）**

字段类型按下面映射建表；字段名照 schema 不改：

| schema 类型 | 在线表通用类型 | 单元格值格式 |
|---|---|---|
| text / longtext | 文本（长文本） | 字符串；长文本放条文、拆解、建议等多行内容 |
| select | 单选 | 传选项名；选项名必须在该表 schema 选项内，不新造选项 |
| number | 数字 | JSON number，不加引号 |
| date | 日期时间 | `YYYY-MM-DD HH:mm:ss`；产品只支持纯日期时按其格式写，时间部分可留空 |
| attachment | 附件 | 附件引用；产品不支持附件时落盘并在对应文本字段写项目内相对路径 |

- **主字段约束**：在线表首字段必须是文本类。纠错记录、进阶记录、禁忌清单、剪映库头与索引这四张表，schema 首字段原为日期或单选；建表时把第一个文本字段提到首位作主字段，原日期／单选字段顺序后移，字段名不改。
- **空值不传**：没填的字段整条省略，不要写空字符串或占位符。
- **批量与超时**：单批 ≤200 条、逐批回查；灌库前按主键去重，灌完回读条数比对预期；超时先 list 回查、只补未成功项，不重发整批。细则正本见 `delivery-rules.md` 第一节"在线表批量写入与回查约定"。

**表用途分类**：第 2、3、8、9、10 表是权威底库表，初始化时按包内底库灌入；第 1、4、5、6、7 表是业务空表，初始化阶段保持空表，不补样例、不填演示行。学员档案的"能力画像"区块建档时全部留空，随片子积累由教练更新。

【第 4 步 · 灌入包内底库】
标准包 47 条（层1 通用剪辑工艺 17、层2 受众、定位与立意架构 13、层3 幼儿场景专属 17）逐条录进第 2 表：编号、条文、层级、出处、局限、状态一项不少；不改写、不合并、不只录标题、不省出处局限；层3 全标"待校准"，层1 层2 保留原文状态。录完报"47 条已录入，三层各多少"。
剪映包 44 条（J01—J44）逐条录进第 3 表，保留全部字段；不把"待核验"改写成"可用"。结构按两个维度看：按端——两端共用 42、APP 专属 2（J05、J15）、PC 专属 0；按性质——J01—J20 判据层、J21—J44 操作底图层（菜单名以我实机为准），其中 J40—J44 为进阶项·L3 准入，基础档练稳、有两条以上同向证据后再教。剪映包开头的官方课程索引（PC 手册 10 节、APP 功能大全 87 讲、APP 零基础入门 10 讲旧版、APP 答疑 10 讲）只作目录引用，不逐条展开，连同库头三条总规矩（官方手册只作索引、标"待核验"的引用前先说没核验过、菜单以实测为准）录进第 10 表。剪映包末尾"不适用／慎用清单"（卡点快剪、蒙版转场、超长叠化、每段换滤镜、多特效叠加、换脸克隆、模板套用）录进第 8 表（类别＝剪映不适用慎用）；"待核验 11 项"（手机端人声分离能否单独导出及是否会员、乐器分离入口名称、转场上限、镜头追踪位置、降噪是否会员、马赛克入口层级、镜头组接相邻摆放与硬切入口、推拉摇跟运镜功能入口名称、全局套滤镜与色彩克隆的作用范围、轻推局部跟随字幕淡入的关键帧落点、长短镜时长搭配的片段拖长缩短操作位置）录进第 9 表。
录完报"44 条已录入，判据 20、操作 24；共用 42、APP 专属 2"。底库读不到就停下，不编 J 条目。

灌库纪律：每张底库表灌入前先按主键（编号）拉线上已有记录去重，只追加缺失项；灌完回读条数与预期比对（标准 47、剪映 44、禁忌 6、待核验 11、库头索引 9），条数不符就告警说明缺哪张表、差几条，不把没灌完说成已灌完；重跑初始化时已有同编号跳过，不重复灌。

【第 5 步 · 给我建档（分组依次弹）】
不要把三组问题一轮全甩出来。先发 A 卡；我答完（或说待补充）再发 B；B 答完再发 C。我一口气把三组都答了，照单收下，不硬拆轮次。
每条消息只推进一个决策点，不跨组连续编号。**先用提问组件把选项做成可点按钮**——组件支持多题同屏就一屏放完，支持逐题就逐题弹；不要默认自己没有这个能力，先试一次，组件不可用或报错再退化。退化形态只有一种：一条消息只问一个问题、最多 3 个选项、编号 1/2/3，末尾写"回个数字就行"；禁止把一屏待确认项排成长编号列表，禁止一条消息里同时问三件事以上。允许挑着答，答不上来记"待补充"，不连环追问。
- A 基本情况：怎么称呼你（以后就这么叫）、带哪个班、大概多少孩子。
- B 干活方式：自己拍自己剪，还是主要剪别人拍好的片子（这条决定以后重点教拍摄还是剪辑，务必答）；一条片子能给多少时间（十分钟内／半小时／一小时以上，这条决定给你"一键成片"还是"精剪"的方案）；只能先练一头，先练拍还是先练剪；拍片用什么、有没有三脚架或云台；剪映用哪一端、什么版本；剪辑熟练度（新手／自己摸索过／常剪）；以前一条片子大概剪多久。
- C 目标与禁忌：最近最想解决的一件事；有没有明确不想改的地方（比如不加字幕、不配乐）。
写进学员档案；能力画像区块这一步留空，不在建档时填。另加"待补充"列。

【第 6 步 · 交完成清单】
一页说清：在线表名称和链接（若走在线表）、10 张表是否建成、主载体是在线表／本地 Excel／Markdown 哪一档（兜底要写明原因）；建了哪些目录、什么路径；各灌多少条（标准应 47、剪映应 44，少了就是没灌完）；两份底库读到没有、各多少条；版本规矩写进 README 没有（一句话复述）；还有哪 11 项剪映功能待我实机核验（用白话写清点哪儿看什么，不甩编号）；能力画像区块已建好、初始为空，以后攒够片子由教练更新；档案还缺什么；以后怎么用（新片子放哪、什么时候叫你、大概给我什么）；现在能开始的第一件事。
再加三句：一段自我介绍（你是谁、擅长什么、怎么配合，三到五行）；示例与额度口径（文字优先，示意图一次最多 2 张、同主题不重复，视频默认不做、要做先经我确认）；交付口径按 `main-prompt.md` 第十一节（诊断／清单／档案／复审默认出单文件 HTML，对话只留三到五行摘要；剪前自检在对话给卡片）。
清单一条消息交付一次，不复述。

【做这些时的规矩】
- 不让我做技术活：音轨分离、转格式、抽帧你自己干。
- 目录和文件建在哪要写明路径，别只说"已经建好了"。
- 提问走分步小卡：建档分组依次弹，后面要我补充信息也一次一张卡、一个决策点；组件优先与退化规矩同第 5 步，不甩一屏编号长列表。
- 端能力不够就明说，给替代方案，不假装完成。
- 档案主载体是当前档位对应的表（在线表／本地 Excel／Markdown）；沙箱／本机只放片子、素材、中间件；档位判断与兜底口径见 `delivery-rules.md` 第一节，降档兜底要在记录里标明当前档位与原因。
- 全程说人话：汇报里不出现 S1-09、S3-15、J04 这类编号，编号只写进档案表；我要问依据你再说编号。
- 她问到能不能对外发、要不要走手续，先提醒确认园所规定与家长授权，不替园方判断授权是否齐备，不展开、不当卡点。
