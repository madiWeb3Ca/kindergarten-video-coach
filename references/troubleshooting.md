# 故障排查与恢复指引

日常建档、查表、交付检查整体按默认流程走；**只有当流程卡住、表读不出来、或老师反馈“打不开／找不到／对不上”时**，再翻这份。

两条总原则：

1. **不静默丢数据**：任何坏表、旧记录先留档（改名 `.bak`），再重建；不直接删旧文件。
2. **不重建两套表**：档位记岔时先核对清楚记录与实际文件，再决定换档；不许“发现表没了就另建一套”，那会把同一份档案拆成两半。

## 先跑自检

```bash
# 档案表完整性：在不在、能不能打开、表头对不对、有没有落在临时目录
python scripts/check_archive.py --project <项目目录>

# 交付物校验：HTML 自包含、截帧已落盘
python scripts/check_output.py --project <项目目录> --html <交付.html> --images <截帧...>

# 一致性自检：底库计数、表骨架与源文件是否一致
python scripts/check_consistency.py
```

`check_archive.py` 退出码：`0` 无硬问题；`1` 有 hard 级问题（表缺失／损坏／表头不符／落在临时目录）；`2` 只有 soft 提醒。输出 JSON 里每条问题带 `code`、`msg`、`next`，按 `next` 处置即可。

## 错误码对照

| 码 | 含义 | 处置方向 |
|---|---|---|
| E_MISSING | 表文件不存在 | 先核对档位是否记岔；确认应为本档后按 schema 重建，记录从案例库兜底补回 |
| E_TABLE_CORRUPT | 表损坏读不出 | 改名 `.bak` 留档，按 schema 重建，再补最近记录 |
| E_SCHEMA_MISMATCH | 表头与骨架对不上 | 对照 schema 补／改表头，改前先备份旧表 |
| E_TEMP_PATH | 表落在临时目录 | 移回项目内「表格」目录，记录写项目内相对路径 |
| E_TIER_MISMATCH | 记录档位与本地文件不一致 | 核对清楚前不自动重建另一套表 |
| E_OPENPYXL_MISSING | 本机缺 openpyxl | 补装后复跑；或确认已按 Markdown 兜底保存 |
| E_DIR_NOT_WRITABLE | 目录不可写 | 换到项目内可写子目录，把实际路径告诉老师 |
| E_ROW_INVALID | 写入行不是有效记录 | 一行记录应为 JSON 对象，按字段名重写 |
| E_L1_PENDING | 在线表待端上回读确认 | 端上核对表与字段齐全，把坐标写回初始化记录 |
| E_NOT_INIT | 项目尚未初始化 | 先跑 bootstrap 初始化 |

## 一、档案表文件打不开（损坏）

**现象**：读表时报损坏、打不开、表格内容乱码；`check_archive.py` 报 `E_TABLE_CORRUPT`。

**判断**：先确认是不是文件被别的程序占用、磁盘满了；排除后仍读不出，判为损坏。

**修复步骤**：

1. 把坏表改名为 `<表名>.xlsx.bak`（或 `.md.bak`）留在原目录，不删除。
2. 打开 `tables/schema.json`，找到同名表，按字段骨架重建空表。
3. 从诊断案例库、Markdown 兜底记录里把最近几条补回；补不全的在记录里标「待补录」，不凭记忆编内容。
4. 复跑 `check_archive.py`，该表 `header_ok: true`、`rows` 与补回条数一致。

**回读校验**：重建后能正常打开、表头与 schema 一致、追加一行再读得到。

**兜底**：若连 `.bak` 都读不出，以诊断案例库与对话记录为准重建；底库表（标准／剪映／禁忌／待核验／索引）可由 `bootstrap.py` 幂等重灌，已存在同编号会跳过。

## 二、表头和骨架对不上

**现象**：`check_archive.py` 报 `E_SCHEMA_MISMATCH`，列出缺字段／多字段。

**判断**：字段名被改写、合并，或旧版表骨架残留。

**修复步骤**：

1. 旧表先复制一份 `.bak`。
2. 对照 `schema.json` 该表字段名：缺的列补上，多余的空列先保留不删（确认无数据再清）。
3. 字段名不得改写；只能追加新字段，不改表名、不合并表。
4. 复跑自检，`header_ok: true`。

**回读校验**：表头顺序与 schema 一致；原有行数据仍在。

## 三、档位记岔：记录与实际文件不符

**现象**：记录写的是在线表／Excel，但本地找不到对应文件，或反过来；`check_archive.py` 报 `E_TIER_MISMATCH`，`table_io.py state` 给出建议档位。

**判断**：常见于换端、换会话后环境变了，或初始化时一次抖动记错档位。

**修复步骤**：

1. 跑 `python scripts/table_io.py state --project <项目目录>`，看 `tier`、`consistent`、`suggest`。
2. 核对项目内「表格」目录实际是 `.xlsx` 还是 `.md`，哪一套有数据就以哪一套为准。
3. 确认应换档后，再在初始化记录里更正档位；有数据的一套保留，空的一套不往里写。
4. 核对清楚前，不自动新建另一套表。

**回读校验**：`state` 返回 `consistent: true`；按记录档位能读到已有记录。

**兜底**：在线表与本地都找不到历史记录，视为新档案起步；可追溯的对话记录逐条补录，标「待补录」。

## 四、目录不可写／无权限

**现象**：建目录、写表时报权限或只读错误；`E_DIR_NOT_WRITABLE`。

**修复步骤**：

1. 换到项目内可写的子目录（或老师授权过的文件夹）。
2. 把实际路径告诉老师，不假装建成了。
3. 不在只读目录、系统临时目录里建档。

**回读校验**：在新路径写一行测试记录再读得到。

## 五、初始化记录被改坏

**现象**：`05_初始化记录.md` 缺「表格档位:」行，或内容损坏；`E_STATE_BROKEN`。

**修复步骤**：

1. 先把原记录备份成 `.bak`。
2. 视为未初始化，重跑 `bootstrap.py`；脚本幂等，已有档案行不覆盖。
3. 重跑后核对底库条数与表数量与记录一致。

**回读校验**：记录含档位行；`state` 能读出档位。

## 六、在线表建不出来（L1 降级）

**现象**：云电脑环境下在线表能力报错、无权限或建表失败。

**修复步骤**：

1. 先把报错或缺口记录下来，不假装已建库。
2. 逐级降级：本地有 openpyxl 走 L2 Excel，缺库再走 L3 Markdown 兜底，不跳过 Excel 直接落 md；在记录里标明「在线表未建成，当前为本地兜底」及具体档位。
3. 对老师只说一句换档，不报技术错误：“这台机器连不上在线表格，我先把档案存在项目里的表格文件，用法一样，以后能搬上去。”

**回读校验**：兜底表能建、能写、能读；记录标明兜底档位。

## 六补、纯手机对话／端上不能建表

**现象**：纯手机对话，不能建目录、不能建表；或端上既无在线表能力，也没有可写的项目目录。

**判断**：当前不具备建档条件，不假装建成了表。

**修复步骤**：

1. 先给老师目录清单让其自行建好；端上有在线表能力才走 L1。
2. 都不可用时只在对话里留记录、不写表；等换到可写项目目录的环境，再落 L3 Markdown 表并把对话记录补录进去。

**回读校验**：落表后 `state` 能读出档位；未落表前不标「已建档」。

## 七、片子打不开／格式不支持／超大

**现象**：片子不是 mp4／mov，体积超大约 500 MB，或端上读不出画面。

**修复步骤**：

1. 先要原片；超大先在本地转码再读，不在对话里硬传。
2. 转码失败就只要关键片段，按时间码说明现象。
3. 不假装看过全片；读不到的部分明确标缺口。

**回读校验**：能播放、能抽帧后再进诊断。

## 八、抽不出截帧

**现象**：端上不支持抽帧，或画面读不出。

**修复步骤**：

1. 明说缺口，只给时间码上能观察到的现象，标「待补帧」。
2. 不贴图、不拿示意图充数。
3. 换可抽帧的环境后再补帧落盘。

**回读校验**：补下的帧写进项目目录并回读一次，才标「已校验」。

## 九、同名片子重交

**现象**：已有同活动记录，老师又交一版。

**修复步骤**：

1. 按版本规矩挂 V2／V3，在原记录上更新，不新建行、不重评全片。
2. 改版复审只查上次建议落没落实。

**回读校验**：同一条记录下版本号递增，历史版本保留可对照。

## 十、长期使用：卡顿或怀疑档案损坏

**触发时机**：攒了一学期片子、换过设备／会话、或老师反馈表变卡、翻不开时。

**定期动作**：

1. 跑 `check_archive.py` 做一次完整性体检；有 hard 问题按上面一～三节处理。
2. 每月把云端档案导出一份到本地留底，别让唯一一份档案只存在云端。
3. 已归档素材先归档再清，不顺删还要用的；容量水位超 80% 先腾已归档部分。
4. 表文件只放项目内「表格」目录，不放临时目录、不放沙箱工作区。

**回读校验**：自检 `pass: true`；本地留底文件能打开、条数与云端对得上。
