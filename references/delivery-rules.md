# 存储与交付纪律

## 一、三档表：怎么选、怎么降

> 本节 L1／L2／L3 指**档案存储档位**；主提示词里能力台阶的 L1／L2／L3 是另一套分级，两者编号同名、互不相干。

### 环境 → 档位映射

| 环境 | 首选档位 | 逐级降级 |
|---|---|---|
| 云电脑（有在线表能力） | L1 在线多维表格 | L1 建不成 → L2 本地 Excel（有 openpyxl）→ L3 Markdown |
| 本地电脑（可读写授权目录） | L2 本地 Excel | 缺 openpyxl／写不进 → L3 Markdown |
| 纯手机对话（不能建目录／表） | 不建档：先给目录清单；端上有在线表能力才走 L1，否则只在对话留记录，可写项目目录时落 L3 md | — |

- 云电脑不一定是"无本地表格组件"：现场可能已装 Python 与 openpyxl，能力以探测为准，不预设老师机／云机都缺组件；cloud 模式仍按 L1→L2→L3 逐级试，上一级确不可用再降。
- 档位探测顺序：先看当前环境能不能建在线表（L1），再看本地能不能建 Excel（L2），都不行才落 Markdown（L3），不跳级。

### 三档落点

| 档 | 落点 | 风险 | 退路 |
|---|---|---|---|
| L1 在线多维表格 | 账号级资源，跨端可读 | 建表失败／无权限 | 降 L2 |
| L2 本地 Excel | `<项目>/表格/*.xlsx` | 缺库 | 降 L3 |
| L3 Markdown 表 | `<项目>/表格/*.md` | 不能计算，只能看 | 修环境后迁移 |

- **主载体**就是当前档位对应的表：在线表、Excel、md 都可能是主载体，不专指在线表。
- 降级**逐级**走：先确认上一级不可用再降下一级，不跳级；每步在初始化记录标明当前档位与兜底原因。
- 档位**只探测一次**，写进 `05_初始化记录.md`；续会话读记录，不重探。
- 查当前档位：`python scripts/table_io.py state --project <项目目录>`；`consistent: false` 时先核对记录与实际文件，不自动另建一套表。
- 换档须老师点头，脚本用 `--tier` 显式指定，不允许"自动发现表没了就重建"——那会把档案拆成两套。
- L3 的 md 表字段名与主档**完全一致**，以后能按主键迁移；追加不覆盖。

### 在线表批量写入与回查约定（L1）

- 单批写入 ≤200 条，逐批处理、逐批回查；条目少就按小批串行。
- 灌库前按主键（首列）拉线上已有记录去重，只追加缺失项，已有同主键可更新，不整批重复灌。
- 灌完回读条数与预期比对：标准 47、剪映 44、禁忌 6、待核验 11、库头索引 9；条数不符即告警，不谎称灌完。
- 写入／删除超时后状态不明：先 list 回查已有记录，分清哪些成功、哪些没成，只补未成功项；禁止不回查就重发整批。
- 空值字段不传；单选传选项名，数字传数值，日期按日期时间格式写。

## 二、片子与表分开存

| 资产 | 放哪 | 理由 |
|---|---|---|
| 片子原件、成片、截帧 | 本地（电脑磁盘） | 体积大，云盘迟早顶 |
| 档案表、诊断记录、台账 | 云端在线表、本地 xlsx 或本地 md | 只有文字，几十上百行 |

云存储配额是**账号级**、跨产品统一计：再开任务、再建项目都不增加容量。满了只有三条路——删已归档素材、扩容、改存本地。

### 片子五目录归属

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `00_待评片子` | 已交来、排队待诊断的片子（实录素材或待评成片），诊断前原件暂存 | 已定稿的交付件、过程分析文件 |
| `01_已评片子` | 诊断完成后的定稿帧、已评成片、定稿诊断报告 HTML；复审 V2/V3 也归这里 | 候选比对帧、切点报告等中间产物 |
| `02_锚点片` | 老师本人自评"觉得不错"的样片及其拆解记录 | 未被她认可的对照样片 |
| `03_素材原件` | 原始拍摄长素材、未剪辑片段、回收备用片段 | 诊断结论、报告、抽帧候选表 |
| `04_技术中间件` | 切点／响度报告、probe 候选帧比对表、定稿核对表、clean 日志、env 探测报告、分离音轨、接触览图等过程产物 | 定稿帧、对外交付的报告 |

- 诊断流转：`00_待评片子` → 分析过程落 `04_技术中间件` → 定稿帧与报告落 `01_已评片子`；锚点片另存 `02_锚点片`，原始长素材归 `03_素材原件`。
- 脚本默认落点：`diag_media.py` 报告、`contact_sheet.py` 览图、`frame_picker.py` probe／clean 日志均落 `04_技术中间件`；定稿帧与已评报告由交付步骤归入 `01_已评片子`，不混在中间件目录里。
- 目录名照此五档，不另起同义别名；手机端写不进目录时先在对话留记录，落本地时归位到对应目录。


## 三、上传前先算容量

```
剩余 = 配额 - 已用
这条片子体积 ≈ 码率 × 时长
  手机 1080p/30fps  ≈ 60—90 MB/分钟
  720p/30fps        ≈ 30—45 MB/分钟
```

- 剩余 > 片子 ×3 → 直接传
- 只够 1—2 条 → 提示先归档一批旧素材
- 明显不够 → 直接建议走本地，别让老师撞上传失败

**沙箱满**：开新工作任务即可（新任务＝新沙箱），但换之前先把正在处理的文件写进项目目录。
**云盘满**：开任务、建项目都无效，只能腾或搬。**任何情况下都不要新建项目。**

## 四、落盘三件套

1. 写到项目目录，不写临时目录
2. 写完**回读**一次（文件在不在、大小对不对）
3. 回读通过才在记录里标「已校验」

中途关对话、换设备、换沙箱都不影响——因为东西在项目目录，不在机器上。

## 五、截帧：附件优先、落盘兜底

| 情况 | 做法 |
|---|---|
| 表支持附件 | 截帧作为附件挂到那条记录 |
| 不支持附件 | 落盘到 `01_已评片子` 同目录，表里存**相对路径** |
| 只用于当场说明 | 可以不落盘，明确告诉老师"这张是示意，不进档案" |

禁止：只把沙箱路径写进表里——片子一丢就是死链，档案里只剩文字。

交付前校验：

```bash
python scripts/check_output.py --project <dir> --html <交付.html> --images <截帧1> <截帧2>
```

hard 级问题（图不存在、落在临时目录、HTML 图片外链）必须先改；soft 级（项目外路径、相对链接）酌情处理。

## 六、月度归档提醒

每月跑一次，先做档案体检，再给老师一句人话：

```bash
python scripts/check_archive.py --project <项目目录>
```

> 这个月项目里新增 N 条片子、M 份报告。要不要导一份到本地存着？

同时看容量水位，超 80% 提示清理**已归档**素材（先归档再删，别顺删要用的）。云端项目建议每月导出一份到本地留底，别让唯一一份档案只存在云端。

**发现表损坏／打不开**：先按 `troubleshooting.md` 第一、二节处置——坏表改名 `.bak` 留档再重建，不直接删旧文件；底库表可由初始化幂等重灌，已有同编号跳过。攒够一学期片子、换过设备或换过会话后，也主动跑一次体检并补一份本地留底。

## 七、环境分流的实话

| 场景 | 走哪 | 代价 |
|---|---|---|
| 单条短片、剪前自检、拍前清单 | 手机＋云电脑 | 上传要等 1—2 分钟，费流量 |
| 成片诊断、批量十几条、锚点片归档 | 电脑本地项目 | 电脑要开着 |

锚点片一律不在手机上做——它必须存下来，存云端就吃配额。

**手机开不了本地项目**：优先建云端项目走 L1；端上在线表也不可用时不假装建库，按纯手机兜底——先在对话留记录，等能写项目目录时再落 L3 md。手机拍的片子最终要落到电脑上处理。
